# 拾数 · 彩票选号实验室

双色球与大乐透参考选号、复式计算、号码保存和开奖核对网站。

**免费新入口：[shishu-lottery.pages.dev](https://shishu-lottery.pages.dev/)** · [原 Worker 入口](https://shishu-lottery-lab.xiaoccchuan.workers.dev)

## 功能

- 单式 1–50 注、复式“几加几”、1–99 倍与大乐透追加，实时计算组合数、金额及一等奖覆盖概率。
- 随机、热号、冷号和遗漏加权选号，蓝球或后区组合可分散覆盖。历史加权没有已验证的预测优势。
- 浏览器本地保存、号码文本导出、JSON 备份导入导出。
- 自定义同步名：像昵称一样自行填写，号码在浏览器中加密后存入 Cloudflare，手机与电脑输入同名即可恢复、合并和同步；兼容原同步码。
- 按官方期号或手动奖号核对，精确统计复式、倍投与追加权益；不计福运奖和派奖。
- 中奖规则对照表与命中个数速查，展示固定奖金、大乐透两档奖池金额、追加说明及历史九奖级规则；核奖页可跳转到所选期号适用的规则。
- 五年公开开奖数据、号码频次和回测结果；在线刷新最近100期，数据源异常时保留快照并明确提示。

## 云端保存

1. 在“我的号码”中点击“启用云端同步”，自行填写2–32个字符的同步名，支持中文、英文字母、数字、下划线和短横线。英文不区分大小写，全角字符按半角处理，首尾空白忽略，不允许内部空格。重名时会提示更换，不会自动连接别人的号码库。
2. 其他设备在“已经有同步名或同步码”中输入同名即可连接。已有8位短码或 `SS1-` 长码仍可使用；可在“管理同步名”中为现有号码库设置名字。设置新名字会增加一个入口，原名字、旧码和已连接设备继续有效，不是撤销旧凭据。
3. 本机已有号码会与云端合并。保存、删除、核奖后自动同步；离线保存后在联网或再次打开页面时重试。
4. “立即同步”可主动获取另一台设备的更新。“断开”只移除本机连接，保留本机与云端号码。

同步名与同步码都相当于号码库的钥匙，持有人可以读取和修改记录。自行起名的强度取决于所选内容，应避免常见昵称；无需另设密码。没有账号、邮箱或密码找回功能。JSON 号码备份不包含同步名或同步码。本地缓存为明文，共享设备使用完请清理浏览器数据。

## Cloudflare 部署

```sh
npx wrangler login
npm run deploy
```

`wrangler.jsonc` 配置静态资源、Worker 和 SQLite Durable Object。首次发布同步功能时，`v1` migration 会创建 `LotteryVault`。不要删除已发布的迁移记录。部署前确认目标账号、Worker 名称和现有资源。

- `GET /api/draws?game=ssq|dlt`：固定官方数据源代理，边缘缓存5分钟；加 `&refresh=1` 强制重新查询，浏览器不缓存接口响应。大乐透并行查询江苏、甘肃体彩，过滤日期重复、倒序或号码无效的源；按期号合并并优先采用江苏体彩的重复期号记录。
- `GET /api/health`：应用版本。
- `POST /api/vault`：新建私人同步空间；`GET` 读取；`PUT` 按版本写入。
- `POST /api/sync-code`：登记同步名或短码的加密映射；`GET`：凭派生令牌读取。映射不可覆盖，原文同步名、短码和长码都不出现在 URL 或请求体中。

号码库的内部 `SS1-` 长码使用256位随机数。浏览器通过 HKDF 派生独立的访问令牌和 AES-256-GCM 密钥；原始长码与加密密钥不会明文发送至服务器。访问令牌通过 HTTPS Authorization 头发送，服务端将其 SHA-256 摘要用于隔离空间，只存储密文。接口校验来源、数据大小和版本号，不提供号码库列表。

8位短码使用32字符表（去除0、1、I、O），共40位随机熵。浏览器先用 PBKDF2-SHA256（600000次）派生材料，再用 HKDF 派生独立查询令牌和加密密钥，将原长码加密封装为不可覆盖的映射。短码只是同一号码库的另一种连接方式，不重建号码库；服务器只收到映射密文与查询令牌。短码的抗猜测强度低于原256位长码，增加慢派生与服务端限流：同一来源地址每5分钟最多20次解析、每小时最多10次登记（计入失败尝试），已有设备日常号码同步不受这组限流影响。号码库、映射及限流状态在同一 Durable Object 绑定的不同命名空间中隔离，无需新增付费服务。

自定义同步名使用 NFKC 规范化和英文小写后，经相同次数的 PBKDF2/HKDF 派生查询与封装密钥，使用独立的 `shishu-sync-name-v1` 域。符合旧8位短码格式的名字沿用旧域及格式，避免同一输入指向不同号码库；`SS1-` 前缀保留给长码。旧8位码的派生参数完全不变。登记失败保留当前号码库与连接，服务端原子拒绝重名；网络响应丢失后可验证映射属于同一号码库再重试。自选名字不保证40位随机熵，不能据慢派生或限流声称常见昵称安全。

同步使用每条记录的逻辑时钟、删除标记和整份密文的版本比较。并发写入冲突后重新读取并合并；不会用本机旧列表直接覆盖云端。每个空间最多200组有效方案，保留最多5000条含删除标记的记录。超限时保留现有记录并提示整理，不会静默裁剪。

## Cloudflare Pages 免费入口

`pages/` 提供另一套 Cloudflare 免费地址入口，使用与 Worker 相同的前端。`/api/*` 通过 Service binding 在 Cloudflare 内部调用现有 `shishu-lottery-lab` Worker，因此浏览器无需直接访问 `workers.dev`。私人同步码仍对应同一个云端号码库；不同域名的本机记录互相独立，输入原同步码可恢复云端号码，仅在本机保存的号码需先导出 JSON 备份再导入。

```sh
npm run build:pages
# 首次发布需要 Pages 权限，且先确认账号下没有同名无关项目
npx wrangler pages project create shishu-lottery --production-branch main --cwd pages --force
npm run deploy:pages
```

首次创建使用 `--force` 明确保留 Pages 项目和 `pages.dev` 地址，防止新版 Wrangler 自动转为 Worker。现有 Pages 项目的后续发布无需此参数。

构建只复制 `public/`、Pages API 入口和路由配置到被 Git 忽略的 `pages/dist/`。静态资源直接由 Pages 提供，只有 `/api/*` 调用函数。保留 Free 套餐即可使用免费额度，无需注册独立域名；`pages.dev` 在大陆的可达性仍需实际网络验证。

本地同时运行 Pages 与现有 Worker，验证真实 Service binding 和 SQLite：

```sh
npx wrangler pages dev --cwd pages -c wrangler.jsonc -c ../wrangler.jsonc --port 8788
# 在另一终端运行
TEST_BASE_URL=http://localhost:8788 npm run test:integration
```

线上测试可设置 `TEST_BASE_URL` 为 Pages 地址，再设置 `TEST_PEER_BASE_URL` 为原 Worker 地址，检查同一随机测试空间在两个入口间读写一致。测试只创建随机、空的加密空间，不使用已有同步码或用户号码。
